## Changes

(each: what, why, checks before → after)

1. **Rank "?" window, Amaterasu-mode Japanese was stale** (progress_dialog.py `_show_rank_info_dialog`). 2. **Debug "Count all notes" could permanently unlock the Sun Diamond** (progress_dialog.py `_check_amaterasu_crossing`). With the debug switch on and a 20,000-note test deck, the "real" crossing path saw 20,000 and wrote `amaterasu_reached` — which is never cleared, is mirrored into the collection (syncs) and shows on the Nakama card. Now it's only set when the debug switch is off. Test `scratch/t/t_sun_debug.py`: FAIL → PASS (a real 20,000 still sets it). The ascension preview itself is unchanged.
3. **Deck names with `_`, `*`, `\` or `"` broke or widened the deck search** (card_state.py new `deck_query`, used by `deck_search` and both kanji_view.py Browser searches). Anki's search treats `_` / `*` as wildcards (a deck `Core_2k` also matched a `Core 2k` / `Core-2k` deck) and an unescaped `"` makes every count fail. Escaped per the Anki manual (`\\ \" \* \_`; `::` unchanged). Test `t_deck_query.py`: 4 FAIL → ALL PASS. harness numbers identical.
5. **Static cleanup (pyflakes 4.0.3, item 6):** no undefined names anywhere (Qt star-import names filtered against PyQt6). Checked first that no module or dev test reaches these names through the cleaned modules. Left: a harmless unused `global` in card_state.set_found_extra and a repeated local import in divine_text. No lens-flare remnants (the only "lens-flare" left is the Amaterasu overlay's own ghosts, a separate feature).
6. **Found / suspended marks could be lost by a crash mid-save; unreadable user files were replaced silently** (overrides.py, history.py, goal.py, nakama.py). `overrides._save` wrote in place (the other user files already used temp + replace): a crash or power cut mid-save left a cut-off overrides.json, which then loaded as *empty*, and the next mark saved over it — every mark gone. And new `overrides.keep_unreadable(path)`: when overrides / kanji / grammar overrides, history.json, goal_days.json or nakama.json exists but can't be read, a copy `<name>.unreadable-<file time>` is kept beside it before anything replaces it (once per broken version; a missing file is normal and backs nothing up). 8. **Text Check showed Shift-JIS subtitle files as garbage** (text_check.py new `decode_text`, used by text_check_view.py `_open_file`). The file was tried as UTF-8, then UTF-16, then cp932 — but Python's `utf-16` without a BOM "decodes" almost any even-length byte string, so every Shift-JIS file of even length (half of them; Shift-JIS is the usual encoding of Japanese .srt/.ass) came out as random CJK characters (4/4 samples). Now: a BOM decides; else UTF-8; else UTF-16 only when NUL bytes show it; else Shift-JIS or EUC-JP, whichever reads more like Japanese; binary junk → the existing "Couldn't read that file as text." Test `t_decode.py`: 10 FAIL → 10 PASS (UTF-8 ± BOM, UTF-16 LE/BE ± BOM, Shift-JIS odd/even, EUC-JP, junk).
